# НСИС — автоскачивание ответов

Финансовый управляющий скачивает ответы в личном кабинете как обычно.
Приложение забирает их из папки загрузок, читает из PDF ФИО должника, дату
рождения и номер дела, называет файл по-человечески, раскладывает по папкам за
день и ведёт журнал. ФУ ни разу не открывает PDF и ничего не печатает руками.

Ничего не устанавливается: приложение — одна страница. Данные никуда не уходят —
всё происходит в браузере, PDF разбирается на месте, файлы остаются на
компьютере.

## Как этим пользоваться

1. Открыть приложение: опубликованный адрес (см. «Размещение») или файл
   `dist/НСИС — ответы.html` с диска либо флешки — работает одинаково.
2. Один раз указать две папки: **куда складывать** (например,
   `Рабочий стол\НСИС` — внутри появятся папки по дням) и **откуда брать**
   (папка загрузок браузера).
3. Дальше просто работать в НСИС. Пока страница открыта, она сама забирает из
   папки загрузок новые ответы. Файлы можно и просто перетащить на страницу —
   тогда никаких разрешений не нужно вовсе.

### Совсем без нажатий: расширение

Полностью автоматическое скачивание умеет только расширение: оно раз в 15 минут
спрашивает у кабинета журнал обращений и складывает готовые ответы в
`Загрузки\nsis-inbox`, откуда их забирает страница. Вкладку держать открытой не
нужно, программ на компьютере не появляется — ставится политикой браузера, как и
сам Chromium GOST. Код лежит в `extension/`, как ставить и что написать в
заявке — в [`docs/EXTENSION.md`](docs/EXTENSION.md).

Это понадобилось, когда выяснилось, что все остальные двери на рабочей машине
закрыты: расширения из магазина запрещены, режим разработчика (а с ним сниппеты
DevTools) закрыт политикой, закладки не срабатывают.

### Чтобы не нажимать «Скачать» вручную

На странице приложения есть закладка **«Забрать ответы НСИС»** — около 3,5 КБ.
Её перетаскивают на панель закладок и нажимают на странице кабинета: она находит
все готовые ответы, скачивает их в папку загрузок под именами
`nsis-<обращение>.pdf` и говорит, сколько забрала. Уже обработанные обращения она
запоминает и второй раз не качает. Дальше файлы подхватывает страница: по имени
она узнаёт обращение, поэтому дубликаты ловятся точно.

Закладка нарочно маленькая: браузер вправе не принять слишком длинный адрес.
Рядом лежит тяжёлый вариант — та же панель, что на странице, но прямо поверх
кабинета, с автопроверкой каждые 15 минут. И тот же код сниппетом DevTools —
если режим разработчика не закрыт политикой.

Сама страница приложения к НСИС обратиться не может, и это не обойти: сессия
кабинета принадлежит его адресу, и браузер не отдаёт её чужой странице.

На диске получается так:

```
Рабочий стол\НСИС\20.09.2026\Борцов Николай Валерьевич — А50-26151-2025 — 20.09.2026 14-35-12.pdf
```

Если ФИО определить не удалось, файл всё равно сохраняется как
`Не определено — …`, и в журнале это видно отдельным статусом — такой ответ не
теряется.

Если папка не выбрана и файл уходит обычным скачиванием, имя пишется латиницей:
`Ivanov Ivan Ivanovich - A50-26151-2025 - 20.09.2026 14-35-12.pdf`. Это не
украшательство — браузер выбрасывает имя целиком, стоит в нём появиться хоть
одной русской букве, и файл превращается в безымянный `download.pdf`. В
выбранную папку имя пишется по-русски.

## Что берётся из ответа

Разбор идёт по сопроводительному письму (первая страница) и началу приложения:

* **ФИО должников** — «в ответ на запрос в отношении …». В одном ответе их может
  быть несколько (например, супруги) — тогда в имени файла первый и «и др.», а
  в журнале все;
* **дата рождения** — «Физическое лицо — … 15.03.1991 года рождения». Нужна
  против тёзок: двух разных «Иванов Иван Иванович» иначе не различить;
* **номер дела** — «№ Дела: А50-26151/2025». В списке обращений его нет, а в
  ответе есть, поэтому он попадает в имя файла: искать по делу удобнее, чем по
  дате. Можно отключить в настройках;
* **финансовый управляющий** — адресат письма, плюс профиль кабинета. Ничего
  переключать вручную не нужно, даже когда за компьютером сменился ФУ.

## Журнал

Журнал лежит файлом `журнал.json` в папке с делами, а браузерное хранилище —
лишь кэш. Благодаря этому страница-приложение и панель на сайте НСИС видят одни
и те же записи, хотя хранилища у них разные: общая у них папка. Браузерное
хранилище можно случайно очистить вместе с данными браузера, а папку с делами —
нет.

Для каждого ответа: ФИО, дата рождения, номер дела, дата ответа, имя файла,
путь, ФУ, hash, статус, число попыток и текст ошибки. У успешных — только
итог, у ошибок — история попыток. Статусы: «Скачано», «ФИО не определено»,
«Пропущено (дубликат)», «Ошибка». Ошибки человеческим языком: «НСИС
недоступна», «Сессия истекла», «Ошибка скачивания», «Не удалось определить
ФИО».

Поиск по ФИО, делу и имени файла; фильтры по дню, статусу и ФУ; открыть PDF,
скопировать путь, «Ещё раз» — она всегда создаёт новый файл рядом:
`Файл (1).pdf`, `Файл (2).pdf`.

## Дубликаты

**Hash содержимого** — основной ключ, когда файл пришёл из папки: тот же ответ,
скачанный второй раз, получает статус «Пропущено (дубликат)» и второй раз не
сохраняется. Когда ответы забираются прямо из НСИС, добавляется более точный
ключ — **идентификатор обращения**: он известен до скачивания, поэтому
обработанное обращение не скачивается повторно вовсе. Кнопка «Ещё раз» обходит
оба уровня.

## Сессия, простой, ошибки

Если приложение не открывали несколько дней, при запуске оно разбирает всё, что
успело накопиться в папке загрузок, — а в режиме панели проходит журнал
обращений целиком и берёт всё, чего у него нет. Сессия НСИС истекает: панель
показывает это и ждёт, пока ФУ войдёт по УКЭП в той же вкладке, дальше сама
определяет ФУ и продолжает. Ошибка одного файла остаётся в его записи и не
мешает остальным; число повторов и параллельных загрузок настраивается (по
умолчанию 3 и 4).

Windows-уведомлений нет. Папка и PDF после загрузки сами не открываются.

## Чего приложение не делает

Не создаёт запросы в НСИС, не ходит в 1С, не вводит номер дела, не отправляет
ничего в интернет, не трогает УКЭП, сертификаты и пароли, не удаляет файлы.
Автопроверка работает только пока открыта вкладка НСИС — программ на
компьютере не появляется.

## Почему именно так

Компьютер в корпоративной среде: расширения браузера ставить нельзя, скрипты
запускать нельзя, неизвестные `.exe` — нельзя, Python и Node нет. Полный разбор
всех возможных способов автоматизации с вердиктами — в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), выбор конструкции и что она
стоит — в [`docs/PLAN.md`](docs/PLAN.md), разбор API кабинета и структуры
PDF — в [`docs/NSIS-API.md`](docs/NSIS-API.md).

Коротко: страница НСИС и локальный файл — разные источники, залезть друг в
друга они не могут, поэтому код работает внутри страницы кабинета. Личный
кабинет оказался обычным приложением поверх JSON-API, так что скачивание идёт
запросом, а не нажатием кнопок.

Три вещи в браузере недостижимы принципиально: проверка при закрытом браузере,
работа без открытой вкладки НСИС и автозапуск. Они требуют программы вне
браузера — одного `.exe`, разрешённого администратором однократно. Код написан
так, чтобы разбор PDF, правила имён, папки, дубликаты и журнал переехали туда
без переписывания.

## Что ещё не проверено на живом НСИС

Честный список — это проверяется первым запуском:

1. разрешает ли корпоративная политика странице доступ к папкам; если нет,
   останется перетаскивание, а файлы пойдут в «Загрузки» с правильными именами,
   но без раскладки по дням — приложение об этом скажет;
2. срабатывают ли закладки на `lk.nsis.ru` (может мешать политика безопасности
   сайта) — если нет, работает сниппет; на саму страницу-приложение это не
   влияет;
3. не требует ли НСИС подписи УКЭП на скачивание готового ответа (в коде
   кабинета подпись для этого запроса необязательна);
4. точные имена полей в `bff/profile` — ФУ определяется и из PDF, так что это
   не критично.

Отдельно стоит убедиться, что автоматизация собственного доступа не
противоречит регламенту НСИС: запросы те же, что делает сам кабинет, но
выполняет их программа.

## Размещение

Страницу установки удобно держать на GitHub Pages: тогда на рабочем компьютере
не надо ничего копировать — открыли адрес и перетащили закладку прямо с него.
Публикация настроена через Actions (`.github/workflows/pages.yml`), каталог —
`dist/`, запуск при пуше в ветку по умолчанию — как бы она ни называлась, так что
после слияния в `main` править ничего не придётся. Один раз нужно включить это в
репозитории: **Settings → Pages → Source → GitHub Actions**.

Размещать безопасно: страница полностью клиентская, ничего никуда не отправляет
и ничего не хранит. Но она будет общедоступной — как и сам репозиторий. Если это
нежелательно, страницу можно просто открывать файлом с диска или флешки: она для
этого и сделана.

## Разработка

```bash
npm install            # только для тестов: jsdom и fake-indexeddb
npm run build          # собрать dist/
npm test               # сборка + проверки
node test/run.mjs ответ.pdf   # прогон разбора по настоящему ответу НСИС
```

Настоящие PDF в репозиторий не кладутся — в них персональные данные должников.
Обязательная часть тестов работает на PDF, который собирается на месте теми же
приёмами, что в ответах НСИС (составной шрифт, шестнадцатеричные строки,
пробел смещением).

* `src/pdftext.js` — текстовый слой PDF без внешних библиотек: zlib через
  `DecompressionStream` и карты `ToUnicode`. pdf.js не нужен — он весит мегабайт,
  а тут около ста строк.
* `src/parse.js` — ФИО, дата рождения, номер дела, ФУ, дата из письма.
  Без DOM и файлов, поэтому проверяется тестами.
* `src/name.js` — правила имён и папок.
* `src/api.js` — клиент кабинета: те же запросы, что делает сам сайт.
* `src/core.js` — два источника (папка и НСИС), общая обработка файла, очередь,
  повторы, дубликаты, состояние.
* `src/store.js` — журнал (IndexedDB), папка с делами и папка загрузок.
* `src/ui.js` — интерфейс в shadow-root: страница-приложение и панель поверх
  кабинета — один код, два режима. Оформление как в ОКБ-анализаторе.
* `build.mjs` — склейка в один файл, без сборщика и без зависимостей.
* `src/grab.js` — та самая маленькая закладка, отдельным файлом: сюда нельзя
  ничего добавлять «заодно», иначе она перестанет помещаться в закладку.
* `extension/` — расширение: фоновая проверка НСИС и скачивание. Вся логика —
  чистые функции, поэтому `test/ext.mjs` проверяет её без браузера.
* `test/smoke.mjs` — прогон собранного файла в jsdom: панель на заглушке НСИС
  (полный путь ответа, дубликаты, истёкшая сессия) и страница-приложение
  (недоступность НСИС, разбор перетащенного PDF).
